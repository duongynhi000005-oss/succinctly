- **yq: a write through a left side that steps into a value that is not a path is a no-op, as in yq** (#4360).
  `(.l + [3])[0] = 5`, `[.n][0] |= 5`, `{"q": .n}.q += 5` and `del((.a + {"c": 1}).b)` raised jq's `Invalid path expression near attempt to access element ...` where yq finds nothing to write through, returns the document unchanged and exits 0. The members of a comma are resolved one by one once one of them fails this way, so `(.a, [.n][0], .s) = 7` still writes `.a` and `.s` and `del([.n][0], .n)` still deletes `.n`. Only a target built from constructs yq's grammar accepts takes the no-op: one holding `foreach`, `reduce`, `try`, `getpath` or `as` keeps the refusal, and a bare computed `del()` target (`del((1 + 2))`) is still refused. `succinctly jq` raises, as jq does. 57 rows captured from yq v4.53.3.
