- **jq: a `foreach` UPDATE that is a `//` over a bind of an outer `$x` no longer refuses on the step after the first** (#5157). `path(. as $x | foreach (.a,.) as $i (.; (($x as {a:$a} | .)) // 5; $i))` on `null` is `["a"]` then `["a"]` in jq and was `["a"]` then `Invalid path expression near attempt to access element "a" of null` (exit 5) here; `// false` (`["a"]`, `[]`), `((..) // 5) // 6`, `|= 9` (`{"a":9}`) and `del` (`null`) differed the same way. jq's `a // b` does not restore its path register when `a` emits a truthy output, so a bind that steps a `null` `$x` against a `null` register has moved it for the next step, while a falsy output backtracks to the entry register and runs `b` from there; the step after the first stored `5`, which is not the register, and met the bind with no register to step from. The register is now carried into that bind, and the `.` it ends on is read as the UPDATE's unchecked output, as it is without the `//`.
