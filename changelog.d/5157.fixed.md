- **jq: a `foreach` UPDATE that is a `//` over a bind of an outer `$x` no longer refuses on the step after the first** (#5157). `path(. as $x | foreach (.a,.) as $i (.; (($x as {a:$a} | .)) // 5; $i))` on `null` is `["a"]` then `["a"]` in jq and was `["a"]` then `Invalid path expression near attempt to access element "a" of null` (exit 5) here; `// false` (`["a"]`, `[]`), `((..) // 5) // 6`, `|= 9` (`{"a":9}`) and `del` (`null`) differed the same way. jq's `a // b` does not restore its path register when `a` emits a truthy output, so a bind that steps a `null` `$x` against a `null` register has moved it for the next step, while a falsy output backtracks to the entry register and runs `b` from there; the step after the first stored `5`, which is not the register, and met the bind with no register to step from. The register is now carried into that bind, and the `.` it ends on is read as the UPDATE's unchecked output, as it is without the `//`; the right operand may be any constant (`5`, `[1]`, `{}`, `(1,2)`). Only a three-argument `foreach` (its EXTRACT judges the emission): a two-argument `foreach` and a `reduce` read the `//` as before. Over 53,550 sampled grid rows (document x INIT x source x bind x tail x `//` wrapper x EXTRACT x `path`/`del`/`|=`) against `/usr/bin/jq` 1.7.1 and a `main` build (`scripts/jq-fold-update-alt-bind-sweep.py`): 5,847 rows that were refused, answered wrongly or worded the error differently now match (303 of them were wrong accepts that `del`/`|=` wrote through), 4 more moved from a wrong write to a refusal, none that matched differ; the same grid over a two-argument `foreach` (53,550 rows) and a `reduce` (32,130) is unchanged. Still different: a comma beside the bind inside the `//` (`(B, 7) // 5`), a `?//` chain behind it, a `| .` after it, and the wrong accepts the two-argument `foreach` and `reduce` UPDATEs of this shape already had.
