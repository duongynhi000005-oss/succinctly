- **jq: an `if $x then ... else ... end` in a fold source now reads the branch `$x`'s value takes, so a destructure of `$x` there raises as jq does** (#4604).
  `path(.a as $x | foreach (1,2) as $i (.; foreach (if $x then $x as {a:$a} | . else . end) as $y (.; .; .); .))` on `{"a":{"b":1}}` is `Invalid path expression near attempt to access element "a" of {"b":1}` in jq and printed `[]` here, and `del`, `=` and `|=` through it deleted or replaced the document; the source analyses read the text of both branches and left any `if` to the by-value route. A marker's value is fixed where it was bound, so one branch can never run: the source is now read with the taken branch (`if $x` and `if $x|not`), only when that branch itself destructures (a bare `.` would hand the source to the routes a literal `.` takes, which refuse a fold body jq answers). Over `scripts/jq-fold-body-register-grid-sweep.py` (119,574 rows, `/usr/bin/jq` 1.7.1, against a `main` build, with three new `if` sources) `ACCEPT_WRONG` went 507 to 483 and `MATCH` 113,844 to 113,868 with no lost match; `jq-path-register-sweep.py --sample 20000 --seed 46042` showed no flip. A bare `$x` destructure and `select($x|not)` on a `null` document in a moved body are still accepted.
