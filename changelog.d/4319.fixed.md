- **yq: a computed key on a scalar the read itself computed answers nothing, as it does for a scalar the document holds** (#4319). `echo scalar | yq '1 as $i | .[$i:][$i]'` printed nothing and exited 0, and `succinctly yq` raised `Cannot index string with number`; the literal spelling (`.[1:][1]`), the pipe (`.[1:] | .[$i]`) and a document-held scalar already answered like yq. The gap was the owned-target index step, which every computed scalar reaches: the slice of a string, a concatenation (`(. + "x")[$k]`), a sum (`(1 + 2)[$k]`), `tostring`, `length`, whatever the key's kind (number, fraction, string, `null`, boolean, array). The rule is yq mode only; `succinctly jq` still raises, as jq does, and a computed array, object or `null` target is indexed as before. A computed key *written* through such a scalar (`(. + "x")[$k] = 5`) still errors where yq leaves the document alone.
