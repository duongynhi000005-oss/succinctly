- **yq: an explicit key whose content is on the line after the `?` no longer swallows the entry after it** (#4532, #1104).
  `?` / `  k` / `x: 1` printed `{"k":"x"}` at exit 0 (the `x: 1` entry lost, `y: 2` / `z: 3` after it turned into `"2":"z"`) and yq prints `{"k":null,"x":1}`; `?` / `  k` / `- item` was `{"k":["item"]}` and yq rejects it. The key content is now read as it is on the `?` line (quoted, flow, sequence, compact mapping, block scalar, properties, multi-line plain scalar), so the key is recorded as waiting for its `:` value and the #1104 rejection of a same-indent `-` covers it. Node properties alone on the content line (`?` / `  &a` / `  k`) are unchanged.
