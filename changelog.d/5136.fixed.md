- **jq: a `reduce` UPDATE of a handler-less `try`/`?` around a bind of `.` that ends on `.` is no longer refused** (#5136). `path(reduce 1 as $i (.; try (. as {b:$q} | .)))` on `{"a":0,"b":false,"c":""}` is `[]` in jq (`[path(..)?]` is `[[]]`, `del(..)` is `null`, `(reduce (1,2) as $i (.; try (. as {b:$q} | .))) |= 9` is `9`): while the bind passes the UPDATE emits the accumulator's own node, and when it raises the `try` empties the UPDATE and the next state is `null` (`try (. as [$q] | .)` on an object still raises `with result null`, as jq). `update_returns_its_input` read a bind of `.` that returns it since #3953 but not through a `try`/`?`, so the UPDATE was read as computing a value and the final emission was refused with `with result <accumulator>` (`[path(..)?]` lost the path). Over 42,000 grid rows (document x bind site x pattern x body x source x INIT x wrapper x context) and 30,000 random fold programs against `/usr/bin/jq` 1.7.1 and a `main` build: about 250 rows that were refused or answered wrongly now match, none that matched differ (also over 24,000 rows of nested folds and `first`/`label`/`limit`/`if`/`//` around the `try`). Neighbouring shapes keep the reading they had: `try (..) // .`, `first(.)` as the bind's body and an INIT that navigates are still refused.
