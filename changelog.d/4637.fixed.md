- **jq: a `?`/`try` around a fold whose `foreach` source destructures the accumulator in a `reduce` body now catches the path error, as jq does** (#4637). `(.a as $x | reduce .[]? as $i (.; foreach (. as [$a] | .) as $y (.; .; .)))? = 9` on `{"a":1}` raised `Invalid path expression with result {"a":1}` (exit 5) where jq 1.7.1 catches the pattern step's error and leaves the document unchanged; `path((...)?)` and `del((...)?)` refused the same way. In the body of a `reduce` whose source moved the register onto an element neither `.` nor a `$x` bound outside is that register, so the refusal is jq's own and is now the catchable `Invalid path expression near attempt to access element 0 of {"a":1}` (jq's exact message when uncaught); everywhere else it stays the uncatchable guess.
