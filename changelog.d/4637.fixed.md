- **jq: a `?`/`try` around a fold whose `foreach` source begins with a destructure of the accumulator in a `reduce` body now catches the path error, as jq does** (#4637). `(.a as $x | reduce .[]? as $i (.; foreach (. as [$a] | .) as $y (.; .; .)))? = 9` on `{"a":1}` raised `Invalid path expression with result {"a":1}` (exit 5) where jq 1.7.1 catches the pattern step's error and leaves the document unchanged; `path((...)?)` and `del((...)?)` refused the same way. In the body of a `reduce` whose source moved the register onto an element `.` is not that register, so a `foreach` or `reduce` source that begins with `. as [$a]` or `. as {a:$a}` raises jq's own error, now the catchable `Invalid path expression near attempt to access element 0 of {"a":1}` (jq's exact message when uncaught). A source that may not reach the destructure (`select(false) | ...`, a `try` that catches it) and the `$x` marker forms keep the uncatchable guess, because there jq's `null` state is refused outside the `try`.
