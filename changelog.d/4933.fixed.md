- **jq: the refusal of a `.` or `$x` destructure run by a fold nested in a `reduce` UPDATE names the step jq raises on, however the source wraps it** (#4933, #4826).
  `path(. as $x | reduce .a? as $i (.; foreach (select($x) | $x as {a:$a} | .) as $y (.; .; .)))` on `{"a":true}` raises `Invalid path expression near attempt to access element "a" of {"a":true}` in jq 1.7.1; it was refused with the same stdout and exit code but the end-of-path wording, `with result {"a":true}`. #4826 named the step only where the destructure was the first stage of the nested fold's source. It is now named wherever the destructure is the first thing the source runs: behind a `select(..)` that passes, inside `[ .. ]`, behind a `//` whose left is never truthy (`[false // (. as {b:$b} | .)]`), in the handler of a `try` that only raises (`[try error catch (. as {b:$b} | .)]`), as the first item of a comma, under `first`/`limit`/`nth(0; ..)`, or after a bind of a constant (`{a:1} as $q | $x as [$a] | empty`). Message only: the refusal, stdout and exit code are unchanged. Over 27,664 sampled rows of the fold-body grid's `rd-nav`/`rd-nava` outers (`scripts/jq-fold-body-message-sweep.py`, a message-aware comparison against `/usr/bin/jq`), 2,780 rows moved from the end-of-path wording to the exact message, none stopped matching and none newly accepts where jq refuses; the grid's own classification (stdout and exit code) is unchanged. Still worded as the end of the path (recorded in `limitations.md`): a destructure behind a bind of a non-constant, in a later comma item or after a stage that emits more than once, and the `foreach` UPDATE/EXTRACT rows where jq itself reads `with result` and the step is named here.
