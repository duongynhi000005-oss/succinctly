- **perf: the x86_64 Linux and Windows release binaries are built with `POPCNT`, and say so at startup if the CPU lacks it** (#5035). On the baseline x86_64 target every per-word `count_ones()` (BitVec `rank1`/`select1`, balanced-parens rank/select, the JSON and YAML cumulative indexes) is a 19-instruction broadword sequence, not the `POPCNT` instruction. On a Ryzen 9 7950X, one source tree built with and without `-C target-feature=+popcnt` and compared with interleaved runs: `yq` -2.9% / -1.9% median over two runs (noise floor -0.4%) and up to -20% on structure-heavy YAML (`empty-items`, `half-empty-items`, `flow`), `jq` -2.9% / -2.5% (noise floor -0.9%); `rank1` -31% / -38%, `select1` -51% / -50% and balanced-parens `rank1`/`select1` -37% / -50% in the micro-benchmarks. The `succinctly-linux-x64` and `succinctly-windows-x64` archives now need an x86-64 CPU with `POPCNT` (Intel Nehalem / AMD K10, 2008, or newer): on an older CPU they print what they need and `cargo install succinctly --features cli` (a baseline build) and exit 1, where they would have died on `Illegal instruction`. The ARM64 archives, `cargo install` and the library are unchanged.
