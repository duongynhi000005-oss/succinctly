- **`succinctly yq` defers a comment after own-line node properties to the next node, and refuses a tag or an anchor given twice on separate lines** (#4851). `a:` / `  !!str # d` / `b: 1` prints `b: 1 # d` as yq does (the comment used to stay on the empty node), and the value below such a line is no longer swallowed (`a:` / `  !!str # d` / `  b: 1` dropped `b`, `a:` / `  !!str # d` / `  x` / `b: 1` read `x: b`). `a:` / `  !!str` / `  !!int` is rejected like yq's `did not find expected key`, where it used to give the node the second tag; a tag with an anchor on the next line, in either order, is still one node's properties. The extra blank line printed after a foot that settles past a sequence closing under a tagged empty item stays recorded in `docs/compliance/yq/limitations.md`.
