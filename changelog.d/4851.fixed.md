- **`succinctly yq` defers a comment after own-line node properties to the next node, and refuses a tag or an anchor given twice on separate lines** (#4851). `a:` / `  !!str # d` / `b: 1` prints `b: 1 # d` as yq does (the comment used to stay on the empty node), and the value below such a line is no longer swallowed (`a:` / `  !!str # d` / `  b: 1` dropped `b`, `a:` / `  !!str # d` / `  x` / `b: 1` read `x: b`). `a:` / `  !!str` / `  !!int` is rejected like yq's `did not find expected key`, where it used to give the node the second tag; a tag with an anchor on the next line, in either order, is still one node's properties. Comment lines between a bare `-` and properties that stand alone on the next line (`k:` / `  - # c` / `    # x` / `    !!str` / `z: 1`) head the node that opens next, as in yq, instead of being placed by the column they were written at: they were `k`'s foot, printed with a blank line after them that yq leaves out, and `.z | key | head_comment` answered nothing where yq answers `c\nx`. At the end of the document yq drops such comments and this keeps them as the root's foot (recorded in `docs/compliance/yq/limitations.md`).
