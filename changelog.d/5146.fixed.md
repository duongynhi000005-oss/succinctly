- **jq: a `reduce` UPDATE of `. as $z | BODY`, BODY handing its input on, is no longer refused** (#5146). `path(reduce (1,2) as $i (.; . as $z | try (. as {a:$q} | .) | .))` on `{}` is `[]` in jq (`[path(..)?]` is `[[]]`, `del(..)` is `null`, `(reduce ..) |= 9` is `9`): the bind moves nothing, `$z` is not returned, and the body's outputs are the accumulator's own node. `update_returns_its_input` read a bind of `.` that returns it, a `try`/`?` and the wrappers a bind chain sits in, but not a plain variable bind, so the UPDATE was read as computing a value and the final emission was refused with `with result <accumulator>` (and `[path(..)?]` lost the path). The variable bind is now read through when its body hands its input on; a body that returns `$z` stays out. Over 40,000 grid rows (document x bind x wrapper x fold kind x source x INIT x context) against `/usr/bin/jq` 1.7.1 and a `main` build: 315 rows that were refused or answered wrongly now match, none that matched differ.
