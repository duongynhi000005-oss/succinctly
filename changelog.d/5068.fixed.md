- **yaml: a plain scalar ended by a comment is not continued by the next line, and a line with nothing to attach to is rejected, as yq does** (#5068). `- a # c` / `  z` read as `["a","z"]`, `k: a # c` / `  z` as `{"k":"a"}` with the `z` gone, and `- a` / `  # c` / `  z: 1` as `["a",{"z":1}]`; yq stops at each (`did not find expected '-' indicator`, `could not find expected ':'`), and so does `succinctly yq` now. A key or an item more indented than the block that holds a plain scalar, and a bare line after a `key: a` or `- a` line that the scalar did not take, are judged the same way. A comment line between the scalar and the line counts as ending it. A bare line led by node properties (`&x z`) is judged like one without. Not changed: a document whose root is a bare plain scalar (its continuation lines that open like an item are read by an older path, and a root followed by stray content is #5070). Two YAML Test Suite cases (`8XDJ`, `BF9H`, invalid YAML that must fail) come off the known-failures list. On 120,000 random small documents the new rejections were about 5,500 documents yq rejects too and 3 documents yq accepts, each already misread before (a node-property or `- `-led continuation line; recorded in `docs/compliance/yq/limitations.md`); across the 13,498 YAML files on one machine no output changed.
