- **yaml: a plain scalar on a line of its own under a `-`, a compact mapping's key or an anchor/tag is rejected when a `key: value` line continues it, as yq does** (#5086, #5083's other containers). `-` / `  a` / `  z: 1` read as `["a"]`, `- k:` / `    x` / `    y: 1` as `[{"k":"x"}]` and `k: &x` / `  a` / `  z: 1` as `{"k":"a"}`, the `: 1` silently gone, where yq stops with `mapping values are not allowed in this context`. The value was scanned from its own indent, so a later line at that indent was no continuation and the `key: value` line was dropped; it is scanned from the indent of the block that holds it now, as under a `key:` (#5083), so `-` / `  a` / `  b` and a sibling after it are unchanged. Not changed, still accepted where yq rejects (all on #5086): a quoted or flow own-line value followed by a deeper line (`k:` / `  "a"` / `  z: 1`), a `-` line between two open blocks (`- k: a` / ` - z`), an explicit key's own-line value (`?` / `  a` / `  z: 1`) and a compact mapping's value at the key's own indent (`- k:` / `  x` / `  y: 1`). Checked against 12,671 YAML files on disk (one, CMake's `presets/schema.yaml`, now reads as yq reads it, none changed otherwise) and 6,000 randomized own-line-value documents against yq v4.53.3: 69 documents yq accepts that `main` read wrongly now match, none that matched stopped matching, and 142 more rejected that yq rejects.
