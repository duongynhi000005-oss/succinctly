- **yq: `length` of a YAML-sourced number on the owned route is the width of its spelling** (#3604, #3597).
  With `a: 2.0`, `b: 1e5`, `c: 1.50`, `.a | length` was already `3` (the cursor route measures the source text), but `to_entries | map(.value | length)`, `map_values(length)`, `with_entries(.value |= length)`, a `*` merge and a `load()`ed file answered the width of the value (`[1,6,3]`) where yq answers the spelling's (`[3,3,4]`), disagreeing with `tostring`. A number written out by the reindex bridge now keeps its spelling for `length` in yq mode; a JSON document's numbers (collapsed on the way in, #3597) and an integer past `i64` keep their widths, and jq mode is untouched. Over 45 YAML and 7 JSON x 2 mode rows against yq v4.53.3 and a `main` build: 0 matches lost. Spellings the YAML materialiser keeps as plain integers or floats (`0x10`, `.5`, `+1`, `1.`, `.inf`) still differ (#2802).
