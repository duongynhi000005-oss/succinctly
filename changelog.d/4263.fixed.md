- **yq: `split(sep)` splits on a non-string separator's text** (#4263). yq reads the separator node's text whatever its tag, so `"a1b" | split(1)` is `["a","b"]`, `"anullb" | split(null)` is `["a","b"]`, `"atrueb" | split(true)` is `["a","b"]` and `"a1.0b" | split(1.0)` splits on `1.0`; a container (`[1]`, `{"a": 1}`) has no text and splits the input into characters; an empty input is `[]` whatever the separator is. `succinctly yq` raised `split input and separator must be strings` for each. `succinctly jq` still requires a string, as jq does. A hex or leading-zero separator read from a document (`sep: 0x10`) still splits on its resolved decimal text, the #2802 spelling gap.
