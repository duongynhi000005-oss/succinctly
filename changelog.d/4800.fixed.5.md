- **jq: `path`/`|=` no longer write the document root when a `//` in a `foreach` UPDATE hands on the output of a left side that moved the register (`null` documents)** (#4800, #4797).
  `null | (. as $x | foreach . as $i (.; (1 | foreach ($x as {a:$a} | .) as $y (.; .; .)) // 5; $i)) |= 9` is `{"a":9}` in jq and was `9` here, with `path(...)` answering `[]` where jq answers `["a"]`; the same behind `// empty`, a nested `//` and a comma inside the left side. The refusal the earlier #4800 entries made for a computed EXTRACT after a register-moving UPDATE was exempted for any UPDATE holding a `//`, because the alternate jq runs after backtracking restores the register. It now judges each output of the `//`: the alternate (and a left operand that moves nothing) states the register it entered with, the left side's own output states what it did, so `path`, `del`, `|=` and `limit`/`?` around the latter refuse with `Invalid path expression with result null`. The same statement is read, where it was refused wrongly before, for the alternate on `true`/`false` and non-`null` documents: `(select(false) | 1 | FE) // 5` and `5 // (1 | FE)` are `[]`, and `(not | FE) // 5` on `{"a":1}` is `[]`, as in jq. Over 19,600 differential rows against `/usr/bin/jq` 1.7.1 (4 heads x 7 `foreach` shapes x 10 `//` wrappers x 2 EXTRACTs x 5 UPDATE wrappers x 7 documents): wrong accepts 1,016 → 20 (612 of them now refuse), no new wrong accept, 1,920 rows that were refused wrongly now match; the 20 left are a comma beside the `//` followed by a stage on a `null` document, and 208 `null`-document `del`/`|=` rows that matched jq only because both of two paths gave the same answer now refuse.
