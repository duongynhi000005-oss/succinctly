- **jq: a fault in a value that also holds an invalid UTF-8 byte is found where jq finds it** (#4349). Where jq detects a malformed value decides the read it resumes at after a caught parse error under `input`/`inputs`. The raw validation stopped on an invalid byte inside a string, though jq substitutes U+FFFD for it before it reads the string, so a string holding both the byte and a raw newline (jq faults at its closing quote), or the byte and a later bad token, resumed at the wrong read and an extra value came out of the read jq discards (`"<0xff>\nnull\n"<0xe2><0x82>` then `<0xac>"`: `"\u20ac"` where jq yields the error). The fault is now looked for in the substituted copy and mapped back to the original byte. A differential against jq 1.7.1 over random multi-file splits with a stray `}`, `[1 2]` and invalid bytes in the pool had 21-45 differing runs per 250 streams before this and 0-17 after; the rest are a resume whose discarded read ends inside a multi-byte character, recorded in `docs/compliance/jq/limitations.md` (#4352).
