- **yq: `{...}` and `[...]` built from nodes of the document keep each node's quote style, flow style, trailing comment and anchor** (#865). `{"a": .a, "b": .b}` over `a: 'single' # ca` / `b: "double" # cb` printed `a: single` / `b: double`; it now prints both lines as yq does, and so do `[.a, .b]`, nested constructions, literals, `length` of a read and arithmetic on reads among the entries (`.a + "x"` takes its left operand's), a node reached through `.` and a construction behind a path (`.c | [.]`), at the cost of the nodes read. yq's own placement is followed: a standalone comment above a node stays with its key, and a non-empty flow mapping after the first entry of a constructed mapping prints as a block. Entries with several outputs (`(.a, .b)`, `.[]`), other computed entries, computed or repeated keys, a construction a later stage reshapes and one wrapped in a `def` print plain, as before.
