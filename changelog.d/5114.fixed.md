- **jq: a caught foreign-`$x` `foreach` behind a `//` with a literal alternate that is a `foreach` UPDATE, with a `$i` EXTRACT, no longer refuses the first step** (#5114). `path(. as $x | foreach (.a,.) as $i (.; (foreach (try ($x as {a:$a} | .)) as $y (.; .; .)) // 5; $i))` on `{"a":null}` is `["a"]` then `Invalid path expression with result {"a":null}` (exit 5) in jq, and `|=`/`del` raise the same message; succinctly refused the first step with `result null` and nothing on stdout. The same `//` behind a no-op `| .` already matched, so a `//` with a literal alternate (`5`, `null`, `false`) that is a `foreach`'s whole UPDATE is now read as that pipe. Over 79,800 grid rows (document x source x caught-bind shape x `//` wrapper x EXTRACT x `path`/`|=`/`del`) against `/usr/bin/jq` 1.7.1 and a build without the change: about 1,900 rows that were refused or answered wrongly now match, none that matched differ. Still different from jq: a `//` with a non-literal alternate (`// .`, `// $x`), which both routes refuse, and a bind in the UPDATE itself over a `null` register.
