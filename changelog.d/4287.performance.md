- **jq: `.[a:b]` of a wide array reads only its range** (#4287). A slice collected every element of the array before taking its range, so a narrow window cost O(length) and a loop sliding a window across a large array was quadratic. It now takes the length from the #4035 memo and reads only the range, from the element index once the array has proved wide, else by one walk that steps over the elements before the range without decoding them. `[range(0; length-8; 16) as $i | .[$i:$i+8] | map(.k) | add] | length` over 50,000 / 100,000 / 200,000 elements takes 23 / 41 / 77 ms (was 2,027 / 9,647 / 40,516 ms): the old time quadrupled per doubling, the new one is linear. The `[.[$i:$i+8][] | .k]` and `[.[$i:$i+8]]` spellings match (22 / 39 / 75 ms and 15 / 26 / 47 ms, was 2,014 / 9,642 / 39,180 ms and 2,085 / 9,610 / 38,674 ms). Output is identical on every row. Release builds, Apple M5 Max, interleaved min of 3; x86_64 not measured. A malformed member inside the range still raises and one outside it still does not.
