- **jq: a `try`/`?` around a foreign `$x` bind chain that ends in a computed value is no longer accepted in a `reduce` UPDATE with a literal INIT on a `null` document** (#4953, #4934 residual).
  `echo null | jq -c 'path(. as $x | reduce 1 as $i (0; try ($x as {a:$a} | 5)))'` raises `Invalid path expression with result 5`; it answered `[]` here, `del(...)` deleted the document and `(...) |= 9` wrote `9`. The same tails `$a`, `"s"`, `[1]` and `{}`, an array or nested pattern, INITs `{}`/`[]`, and the tail inside a `limit`, `first`, `label`, comma or `if` around the `try` were accepted. #4934 carried the register into such a body for a chain ending in `.`; a chain ending in anything else was not one of the shapes that mark the UPDATE's binds as being in tail position, because that check did not read a `try`/`?` or the wrappers around one. It now reads them through (`hands_outputs_on`, the walk `foreign_bind_chain_returning_dot` and `is_single_output_bind` share), so the register is carried in and the step judged against it, as for an uncaught chain. Also names the tail's value in the error (`with result 0`) where a non-`null` document named the bind's `null`. Pinned by `tests/jq_cli/i4953.rs`; `scripts/jq-reduce-update-bind-sweep.py` gained the wrapper shapes; its 104,976-row grid against `/usr/bin/jq` moved 675 wrong accepts, 297 wrong refusals and 1,584 wordings to a match, none stopped matching and none newly accepts. Still a wrong accept (recorded in `limitations.md`): the same `try` around a `?//` chain, 90 rows of that grid and unchanged.
