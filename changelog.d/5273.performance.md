- **jq: `reduce range(N) as $x ({}; .a |= (. // []) + [$x])`, `.a = .a + [$x]`, `.a = (.a // []) + [$x]` and `.a += {($x|tostring): 1}` extend the one growing value where it is** (#5273). Growing a single array or object in one field was quadratic in jq too, but ours had a 12x larger constant on the `|=`/`=` spellings: they evaluated the old value or the whole accumulator through the evaluator, then summed a clone of the old value, so nothing could extend in place. The step now answers those shapes itself and, for two arrays, objects or strings, takes the old value out of its slot for the `+` (`.a += R` and `.a |= . + R` too), which makes the loop linear. Any other pairing, a right side that reads `.`, and a step that raises still take the evaluator's route and text. Measured on an Apple M5 Max (release builds, interleaved, min of 3, ~80 ms process-spawn floor included, output identical): `.a |= (. // []) + [$x]` 0.31 s → 0.08 s at 5,000 steps, 0.99 s → 0.09 s at 10,000, 4.05 s → 0.09 s at 20,000 (jq 1.7.1: 0.31 s at 20,000); `.a = .a + [$x]` 0.33 s → 0.09 s, 1.11 s → 0.08 s, 4.14 s → 0.08 s; `.a = (.a // []) + [$x]` 0.31 s → 0.08 s, 0.99 s → 0.08 s, 3.98 s → 0.09 s; `.a += {($x|tostring): 1}` 0.62 s → 0.10 s, 2.35 s → 0.11 s, 9.89 s → 0.12 s (jq: 1.32 s at 20,000); `.a += [$x]` 0.12 s → 0.11 s, 0.23 s → 0.11 s, 0.75 s → 0.12 s. The unrelated counting folds are unchanged (`.i += 1` over 1,000,000 steps 0.12 s → 0.11 s).
