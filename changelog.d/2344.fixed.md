- **yq: `del()` through a mid-path `.[]` before a slice-run and a field now raises per element, like yq** (#2344). `del(.a[][0:2].x)` on `{"a":[[1,2,3],{"y":1}]}` printed the document unchanged where yq fails with `cannot index array with 'x'`: the path was classified once from a prefix the classifier cannot walk past a `.[]`, so it always answered "no-op". It now defers to `delete_at_path`'s per-element walk, which already re-classifies each element. The call fails when any element is not a string (yq slices a mapping, int, bool, `null` or array to an empty sequence, so `.x` is parsed as an index), a string element and an empty `a` stay a no-op, `.x?` suppresses, and a comma sibling does not rescue it. Without a `.[]` the same rule now covers a mapping, int or bool target (`del(.a[0:2].x)` over `a: 5`), which was only applied to arrays and `null` (#2333).
