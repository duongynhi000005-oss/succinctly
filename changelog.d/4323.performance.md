- **jq: a literal-bound slice read, `.[2:][0]`, no longer builds the slice** (#4323). #4195, #4288, #4315 and #4317 fused `E[a:b]` with a computed bound followed by a read; a literal bound (`.[2:]`) has no native arm in the generic evaluator, so it fell to the full evaluator, which converted every element of the array on each read. `[range(length) as $i | .[2:][0] | .a.b] | length` over 4,000 `{"a":{"b":i}}` elements took 10.8 s on a Ryzen 9 7950X and now takes 5.9 ms; 2,000 elements 2,686 ms to 4.4 ms, 1,000 elements 641 ms to 3.4 ms. The old time quadrupled per doubling; the new one grows 1.3x per doubling, where the `.[$i]` floor grows 1.3x. `[-1]`, `length`, `first`, `last`, a negative end (`.[:-2][0]`), a `?` on either stage and a computed index (`.[2:][$i]`) are covered, 4,000 elements run in 2.8-6.6 ms against 10.1-11.2 s. A bracket read behind navigation (`.a[2:][0]`) is covered; a navigated slice followed by a separate `| length`/`first`/`last` stage (`.a[2:] | length`) is not yet. Release builds, 7950X pinned to one core, interleaved min of 3, output identical to the old binary on every row; the unfused spelling `(.[2:])[0]` is unchanged (the control). Like the computed form, the fused read converts only the element it names, so a malformed value elsewhere in the array no longer raises (`.[0:3][0]` on `[1,1.2.3,3]` is `1`; jq rejects the document at parse), recorded in `limitations.md`. Library `succinctly::jq::eval` over a materialized value is a separate route and unchanged.
