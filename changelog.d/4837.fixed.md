- **jq: `path`/`|=` no longer write the document root when a `//` behind or ahead of a stage in a `foreach` UPDATE hands on the output of a left side that moved the register (`null` documents)** (#4837, #4800).
  `null | (. as $x | foreach . as $i (.; ((1 | foreach ($x as {a:$a} | .) as $y (.; .; .)) // 5) | .; $i)) |= 9` is `{"a":9}` in jq and was `9` here, with `path(...)` answering `[]` where jq answers `["a"]`; the same with `| select(true)`, `. | (...)`, `first(...)`, `try (...)` around the `//`, and for `(1 | FE) | (. // 5)`, whose `//` moves nothing and restores no register. #4836 judged a `//` per output only when it was the whole UPDATE; it is now read through stages that move nothing, so the left side's output refuses with `Invalid path expression with result null` and the alternate (`(select(false) | 1 | FE) // 5`) stays `[]`. Over 40,320 differential rows against `/usr/bin/jq` 1.7.1 (15 heads x 6 `//` wrappers x 16 stage shapes x 4 writes x 7 documents), `main` as the base: wrong answers 510 → 70, no new wrong answer, and 168 `null`-document `del`/`|=` rows that matched jq only because deleting or writing the root gave the same result as `["a"]` now refuse; the 70 left are `(.a? // 1) | FE` and two stages each holding a `//`.
