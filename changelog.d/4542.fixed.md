- **yq: `del()` through a `.[]` after a slice-run and a field now raises per element, like yq** (#4542). `del(.a[0:2][].x)` on `{"a":[[1,2,3],{"y":1}]}` printed the document unchanged where yq fails with `cannot index array with 'x'`: the classifier's walk past the slice-run had no `.[]` arm and gave up. It now fans out over the sliced elements and applies the tail to each, so the call fails when any element is an array (even an empty one) and stays a no-op for a mapping, scalar or string element, an empty or out-of-range slice, and an index tail; `.x?` suppresses and a comma sibling does not rescue it. The same walk now slices a mapping to its key/value children (`del(.a[0:2][1].x)` over `a: {y: [1]}` fails on the value `[1]`) and type-checks the steps before the run, so `del(.a[0:2][].x)` over a root array fails on `.a` and `del(.a[].b[0:2].x)` over `a: [[1]]` fails on `.b`, both of which used to no-op, and the check also runs when the path ends in a further slice (`del(.a[0:2][].x[0:1])`).
