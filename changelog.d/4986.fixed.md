- **jq: a `?//` chain on `.` in a `reduce` UPDATE with a navigating INIT over `first(..)` is no longer accepted where jq raises** (#4986, #4969 residual).
  `echo '{"a":{"b":1}}' | jq -c 'path(reduce first(..) as $i (.a; . as {a:$a} ?// $a | $a))'` raises `Invalid path expression with result null`; it answered `["a"]` here, and `del(...)` deleted `.a` and `(...) |= 9` wrote through it (`limit(1; ..)` and `nth(0; ..)` likewise). The source's only element is the ambient `.`, which moved nothing, so jq's register is still where INIT left it (`.a`) and the accumulator is its node, so the first alternative's pattern step passes; `first(..)`'s element carried no position of its own, so #4969's exemption did not apply and the retry onto the bare `$a` kept the accumulator. A source that is `..` cut to its first output is now read as that ambient element. Pinned by `tests/jq_cli/i4986.rs`; a 12,150-row grid against `/usr/bin/jq` moved 9 wrong accepts and 27 wrong refusals to a match, none lost, no wrong accept left.
