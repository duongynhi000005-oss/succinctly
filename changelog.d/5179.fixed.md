- **jq: a `foreach` UPDATE's `catch` handler is placed on a step whose pattern lands on the state, and on one whose nested pattern does not raise** (#5179). `[path(. as $x | foreach (.a,.,.a) as $i (null; try (foreach ($x as {a:$a} | .) as $y (0; .a?; $y)) catch $i; .))?]` on `{"a":{"b":1}}` is `[["a"],[],["a"]]` in jq and was `[["a"]]` here (the first step's `catch $i` leaves the node `.a`, which the second step's pattern lands on), and `[path(. as $x | foreach (.a,.) as $i (.; not | try (foreach ($x as {a:{b:$b}} | .) as $y (null; error("x"); $y)) catch 7; $i))?]` on `{"a":{"a":null}}` is `[["a"],[]]` and was `[]`; the same filters in `path`, `del` and `|= 9` follow. Whether jq's register is the state is a question of node identity, which a value cannot settle and the state's position can: the fold keeps where the accumulator was last reached, and a landing at that path is the state, one at another path (an equal value, say) is a different node. A one-entry nested pattern is followed to the node its innermost entry reaches. Read only for a step that binds one bare `$name`, with no value head before the nested `foreach`. Over seven 8,000-row grids against `/usr/bin/jq` 1.7.1 (1,056 rows fixed) no row that matched lost its stdout or exit code, and no refusal turned into a wrong answer; 15 rows where both raise name the other refusal in the message.
