- **jq: `path`/`|=` no longer write the document root when a `//` stage sits ahead of the register-moving stage of a `foreach` UPDATE, or when two stages each hold a `//` (`null` documents)** (#4843, #4837, #4800).
  `null | (. as $x | foreach . as $i (.; (.a? // 1) | foreach ($x as {a:$a}|.) as $y (.; .; .); $i)) |= 9` is `{"a":9}` in jq and was `9` here, with `path(...)` answering `[]` where jq answers `["a"]`; the same for `((1 | FE) // 5) | ((1 | FE) // 5)` (`["a","a"]`, `{"a":{"a":9}}`). A `//` stage in a pipe now hands on the register its alternate (or a left operand that moves nothing) stated, so the stage after it runs from that register, and the whole pipe is read stage by stage instead of exempted whole; the rows now refuse with `Invalid path expression with result null`, while `(.a? // 1) | ((select(false) | 1 | FE) // 5)` and the other shapes where no `foreach` runs stay `[]`. Over 31,500 differential rows against `/usr/bin/jq` 1.7.1 (15 stage shapes squared x 5 wrappers x 4 writes x 7 documents), `main` as the base: 612 wrong accepts on `null` now refuse, none remain, 784 rows that differed from jq now match it, and the only rows that changed from matching jq are 204 `null`-document `del`s that matched only because deleting the root gave the same `null` as deleting `["a"]`.
