- **yq: a string literal keeps every backslash sequence yq does not decode, so `test("\d")` parses** (#4916).
  Real yq's lexer decodes `\n \t \r \b \f \a \v \" \\` in a filter string literal and keeps any other backslash sequence as written; `succinctly yq` used jq's table, which decoded `\u` and `\/` (`"\u0041"` printed `A` where yq prints the six characters `\u0041`) and rejected the rest as `invalid escape sequence`, so a regex such as `test("\d+")`, `split("\-")`, `sub("\s"; " ")` or `capture("(?<n>\d)")` was a parse error. 147 rows captured from yq v4.53.3 now match (each ASCII character after a backslash, `\u` forms, a multi-byte character, an escape beside an interpolation, object keys, path steps and regex builtins), in `tests/yq_cli/i4916.rs`; jq mode keeps its own table. Two existing tests that wrote `\ufffd` / `\u0000` in a yq filter (their expectations came from probes whose shell had already decoded the escape) now spell the character. A dotted path step's quoted name (`.x."\tb"`) is read raw, as yq does, so it selects the key with a literal backslash. Still different (recorded in `limitations.md`): a run of backslashes ahead of `\(`, an unclosed `\(`, a `\"` inside an interpolation, and the regex dialect.
