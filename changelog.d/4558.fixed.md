- **yaml: a `:` before a flow indicator is key or item content, and a flow entry cannot open with an empty key, as in yq** (#4558).
  `{a:}` is `{"a:":null}` in yq and read `{"a":null}` here, `[a:]` is `["a:"]` and read `[{"a":null}]`, and the same for `{a:,b:}`, `[1 b:]`, `[a, b:]` and `x: {a:}`; the key scanner and the pair detector stopped at a `:` straight before `,`/`]`/`}`, where yq keeps it. An entry that opens with `:` and a blank (`[: x]`, `[a, : x]`, `{: x}`) or any flow-mapping key that opens with `:` (`{:x}`, `{:}`) is an empty key yq rejects ("did not find expected node content") and printed `[{"":"x"}]` here; a `:` glued to item text (`[:x]`, `[:]`) is still an item. `succinctly yaml validate` now rejects a second pair `:` before the next `,` (`{a: 1 b: 2}`). Three YAML Test Suite cases that are valid YAML 1.2 but rejected by yq (`CFD4`, `FRK4`, `NKF9`) move into the known-failures manifest: we follow yq. Swept 28 flow shapes against yq v4.53.3: 14 differing rows -> 0 (the `[? : x]` quirk yq rejects is not covered).
