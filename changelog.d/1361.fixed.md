- **yq: a query that is a comma of document nodes (`.x, .y`) keeps the comments, style and `&anchor` marks of each result** (#1361).
  `printf 'x: &a {p: 1}\ny:\n  q: *a\n' | yq '.x, .y'` starts with `&a {p: 1}`; `succinctly yq` printed `p: 1`. `x:\n  p: 1 # note\ny:\n  q: "str"` lost `# note` and the double quotes, and a flow sequence read twice (`.l, .l` on `l: [1, 2]`) came out in block style, though each half of the comma kept all three on its own. The branches that answer nodes of the document now stay cursors, as `.[]`'s results do, so the output is byte for byte what `--arg z 1 '.[]'` prints for the same nodes. Over 38 comma queries on four YAML documents (plain and `-o json`) and two JSON documents under `jq`, 27 outputs changed, all of them plain YAML and each now showing the comments, style and anchors yq shows; `-o json` and `jq` (against `/usr/bin/jq` 1.7.1) did not change. A branch that is not a node (`.x, (.y | length)`, `.x, 1`, an absent key in `.x, .zz`) still turns the nodes before it into copies, and a comma inside a bigger expression (`[.x, .y]`, `(.x, .y) | f`) is read by that expression as before.
