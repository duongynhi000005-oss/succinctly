- **yq: a comma-grouped `del()` sibling that iterates a missing key and keeps going no longer raises** (#2380). `del(.missing[].x, .y)` printed `Cannot iterate over null (null)` where yq prints `{}`: the sibling pre-pass that tolerates a `null` `.[]` (#2324) only recognised a *trailing* `.[]`, so `.missing[].x` (and `.missing[].x.z[0]`, `.missing[].x[]`, `.n[].x` over a stored `null`, `.[5][].x` past the end of an array) fell through to the read-based resolver that rightly raises. It now also takes a `.[]` followed by static path, in either position of the group, and a prefix that is a scalar rather than `null` (`del(.s[], .y)` over `s: 5` raised `Cannot iterate over number (5)`; yq leaves `s` alone). A sibling with a negative or computed index still declines the whole pre-pass, as before (yq's own answer there depends on order).
