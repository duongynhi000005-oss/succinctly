- **jq: a `try`/`?` around a foreign `$x` bind in a `reduce` UPDATE with a literal INIT is no longer accepted on a `null` document where jq raises** (#4934, #4932 residual).
  `echo null | jq -c 'path(. as $x | reduce 1 as $i (0; try ($x as {a:$a} | .)))'` raises `Invalid path expression with result 0`; it answered `[]` here, `del(...)` deleted the document and `(...) |= 9` wrote `9`. The register was withheld from the `try` body, so the bind step on a `null` `$x` (which jq passes by kind against a `null` register) was refused as exact, the `try` swallowed it, the UPDATE read as empty and the state as `null`, which a `null` register accepts. A `try`/`?` without a handler around such a chain is now read through as a comma, `label`, `first`/`limit` and `if` are (#4932), so the register is carried in and the step is judged against it. The same change answers what was a wrong refusal: `INIT = .` behind the `try` on `{"a":{"b":1}}` is jq's `[]` (it refused with `with result <document>`), and a non-`null` document names the literal (`with result 0`) rather than the bind's `null`. A 77,760-row grid against `/usr/bin/jq` (six INITs x six sources x six binds x twenty UPDATE shapes x six documents x `path`/`del`/`|=`) moved 1,260 wrong accepts, 360 wrong refusals and 1,062 wordings to a match; none stopped matching and none newly accepts. Pinned by `tests/jq_cli/i4934.rs`. Still a wrong accept (recorded in `limitations.md`): the same `try` around a chain that ends in a computed value (`$x as {a:$a} | 5`, `| $a`) or a `?//` chain, 225 rows of that grid and unchanged.
