- **yq: a write behind a static navigation keeps the navigated subtree's comments, flow style and quoting** (#5286). `.a | .b = 5`, `.a | (.z = 3)`, `.a | del(.b)` and `.a | sort_keys(.)` printed the subtree in block style with every comment and quote dropped, where yq prints `# above b`, `b: 5 # b trail`, `c: [1, 2] # flow` and `c: 'r'` as the document has them. The write now runs on the navigated node as a document of its own, as #2679 did for a metadata write (`.a`, `.a.b`, `.[0]`, or a pipe of them; not in a document that holds an alias, and not for a write that reads `key`, `path`, `line` and the like). A write that replaces a container with another shape still drops the comment on the replaced one, with or without a navigation (#5258). On a 1.6 MB document (Apple M5 Max, release builds, interleaved, min of 7, process-spawn floor included) the write costs what the same write without a navigation costs: `.meta | .v = 5` 85 ms → 84 ms, `.items[5] | .id = 9` 85 ms → 83 ms, and `.items | .[0].id = 9`, whose navigated subtree is almost the whole document, 136 ms → 196 ms (`.items[0].id = 9` without a navigation: 192 ms).
