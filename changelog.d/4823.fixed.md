- **jq: an uncaught nested `foreach` behind a `null` value head in a `foreach` UPDATE over a moving source raises at the pattern's step on a foreign `$x`** (#4823, #4800).
  With `P = null | foreach ($x as {a:$a} | .) as $y (.; .; .)`, `path(. as $x | foreach .a as $i (.; P; .))` on `{"a":null}` raises `Invalid path expression near attempt to access element "a"` in jq and answered `["a"]` here, and `(...) |= 9` wrote `{"a":9}` and `del(...)` deleted the key (likewise with sources `(.a,.)` and `(.,.a)`): the `null` head's value reads as jq's register by kind, so the `$x` bound at the root went unchecked. A `$x` that holds a container is never the `null` register, so it is now read as foreign and the step refuses, as the head-less form already did. A `try` around the inner `foreach`, a `null`/boolean `$x`, and heads of another kind are unchanged. Over 27,720 differential rows against `/usr/bin/jq` 1.7.1 (heads x sources x destructures x inner folds x `path`/`del`/`|=` x `try`/uncaught x 5 documents): 100 rows that differed now match, none that matched differ.
