- **jq: a `reduce` UPDATE that wraps a bind of `.` that ends on `.` in `first`, `limit`, `nth(0; ..)`, a comma or an `if` is no longer refused** (#5140). `path(reduce . as $i (.; first(. as {a:{a:$q}} | .)))` on `{"a":{"b":1},"b":2}` is `[]` in jq (`del(..)` is `null`, `(reduce (1,2) as $i (.; limit(1; . as {b:$q} | .))) |= 9` is `9`, `[path(reduce (1,2) as $i (.; first(. as {b:$q} | .)))?]` is `[[]]`): every output of the UPDATE is the accumulator's own node, so the register jq's final check reads is INIT's however far the bind navigated. `update_returns_its_input` read `.`, a pipe, a `label`, a handler-less `try`/`?` (#5136) and a bind of `.` that returns it, but not the wrappers the bind chain of the same UPDATE sits in, so the UPDATE was read as computing a value and the final emission was refused with `with result <accumulator>` (and `[path(..)?]` lost the path). It now reads `first`, `limit` with a nonzero constant count, `nth(0; ..)`, a comma whose every item returns the accumulator, and an `if` whose condition cannot move the register and whose branches do. A `//` (its right operand is not the accumulator when the left is falsy), an `if` whose condition navigates and a comma item that computes a value keep their refusal. Over 24,000 grid rows (document x bind site x pattern x wrapper x fold kind x source x INIT x context) against `/usr/bin/jq` 1.7.1 and a `main` build: 312 rows that were refused or answered wrongly now match, none that matched differ.
