- **yq: a JSON object key `<<` is an ordinary key, not a YAML merge key** (#3600). A JSON document has no merge key: `echo '{"<<":1,"a":2}' | yq -p json -o yaml '.zz = 1'` prints `"<<": 1` / `a: 2` / `zz: 1`, and `.a.y` over `{"a":{"<<":{"y":1},"b":2}}` is `null`, with `keys`, `to_entries`, `length`, `has("<<")` and `[.[]]` counting the entry. `succinctly yq` resolved it as a merge key whatever the source, so a write, `del`, `sort_keys` or `-P` dropped the entry (key and value) from the YAML output and a read saw the merged-in members. YAML input is unchanged. yq's JSON *encoder* drops a `<<` entry from JSON output altogether; `succinctly yq` keeps it there (a silent loss of a key and its value), recorded in the yq limitations.
