- **jq: a `reduce` with a navigation INIT and an UPDATE that hands the accumulator back is no longer refused** (#5148). `path(reduce (1,2) as $i (.a; (. as {b:$q} | .)))` on `{"a":{"b":1}}` is `["a"]` in jq (`[path(..)?]` is `[["a"]]`, `(reduce ..) |= 9` is `{"a":9}`): INIT's navigation leaves jq's register on `.a` and the accumulator is that node, so UPDATE meets `.` on the register exactly as after `INIT .`. The carry-forward that an UPDATE returning its input leaves the accumulator on the register was gated on an INIT that moves nothing, which a field navigation fails, so the UPDATE was read as computing a value and the final emission was refused with `with result <accumulator>` (and `[path(..)?]` lost the path). An INIT that is navigation alone (`.a`, `.a.b`, `.a?`, `.a|.`, `first(.a)`, a comma of them, `.["a"]`) is now admitted; an INIT that computes (`.a|tostring`, `null`, `{}`) keeps its reading. Over 100,000 grid rows (document x INIT x bind x wrapper x fold kind x source x context) against `/usr/bin/jq` 1.7.1 and a `main` build: 180 rows that were refused or answered wrongly now match, none that matched differ.
