- **jq: a `foreach` UPDATE `if` whose `then` holds the caught `foreach` is resolved as its `else` arm on the steps that run it** (#4800).
  `[path(. as $x | foreach .a as $i (.; if .a then foreach (try ($x as {a:$a} | .)) as $y (.; .; .) else null end; .a))?]` on `{"a":null}` is `[["a","a"]]` in jq and was `[]` (`path` raised `Invalid path expression near attempt to access element "a" of null`): the `if` was resolved whole, so the `foreach` in the arm that did not run withheld the tracking of the `null` the literal arm stores.
  A bare `if` UPDATE whose step took one arm now resolves that arm alone, as jq runs it; the same holds under `path`, `del`, `|=`, `try ... catch`, `?`, an `elif` and a `(FE, empty)` `then`.
  Against `/usr/bin/jq` 1.7.1, three random 12,000-row samples of a 907,200-row grid (`if`/`elif` UPDATEs with the `foreach` in a `then` x 19 `else` arms x 6 sources x 7 EXTRACTs x 5 write contexts x 12 documents) fix 12, 20 and 26 rows, lose none and change no other row; two control samples without the `foreach` change none.
