- **jq: a `foreach` UPDATE `try (if C then A else B end) catch H` answers on the `foreach`'s last step where the handler hid the arm the state ran** (#5113). `{"b":true}` with `path(. as $x | foreach (.) as $i (null; try (if .b then null else FE end) catch 1; .a))` (`FE` a `foreach` over `try ($x as {a:$a} | .)`) is jq's `["a","a"]` where it was refused with `near attempt to access element "a" of null`: the computed `else` the `null` state took is now resolved as `try (FE) catch 1`, as the bare `FE` is. And an `if` whose condition raises on the state (`.a` of the stored `1`) never reaches an arm, so a literal handler answers: `{"a":{"a":null}}` with `foreach (.) as $i (1; try (if .a then 1 else FE end) catch 1; $i)` is jq's `[]`. Both are read only for a single pattern with no `?//` chain, since a retry runs UPDATE again on the stored literal. Over 100,000 rows of `scripts/jq-foreach-update-if-arm-sweep.py` against `/usr/bin/jq` 1.7.1 and a `main` build, no row that matched jq was lost and no refusal turned into a wrong answer.
