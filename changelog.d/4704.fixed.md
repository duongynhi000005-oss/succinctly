- **jq: a caught destructure of `.` as a `foreach` source in a moved `reduce` body now empties the source, as jq's does** (#4704).
  In `path(. as $x | reduce .[]? as $i (.; foreach (SRC) as $y (.; .; .)))` on `{"a":true}`, `SRC` of `false // ((. as {b:$b}|.)?)` or `try (. as {a:$a} | .) catch empty` raises `Invalid path expression with result null` in jq (the pattern step raises in the moved body, the `?`/`try` swallows it, the `reduce` UPDATE emits nothing and its `null` state is refused at the end of the path) and printed `[]` here, so `del`, `=` and `|=` through them wrote where jq refuses. `try (false // error) catch (. as {b:$b}|.)` raised nothing for the same reason (`certainly_raises` did not see through a falsy `//`) and now refuses too. Nested wrappers (`try (try X catch empty) catch empty`, `(X?) // empty`) are read the same way. A truthy left, a handler that emits and a `null` document are unchanged. Still answered where jq raises: the `$x` spellings (`false // ($x as {b:$b}|.)`, `try error catch ($x as {b:$b}|.)`), which belong to #4709, and a handler that rethrows or empties without being the literal `empty`.
