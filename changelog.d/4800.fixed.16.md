- **jq: a `foreach` UPDATE that binds `.` with a single pattern keeps jq's answer under a `first`, `limit(1; ..)` or `nth(0; ..)` over a comma that holds a non-bind sibling behind the bind** (#4800).
  `path(foreach (1,2) as $i (.; first((. as {a:$q} | .), 7); empty))` on `{"a":null}` prints nothing in jq (the bind's output is taken and the `7` behind it is never run, so the state is the register's own node and the EXTRACT's value is the answer) and raised `Invalid path expression with result {"a":null}` here; `[path(..)?]` answered `[]` where jq answers `[["a"]]`, and a `$i` EXTRACT named the UPDATE's own state where jq names the EXTRACT's `result 1`. The same holds for `limit(1; ..)`, `limit(0.5; ..)`, `nth(0; ..)`, a nested comma led by the bind (`first(((B), 7), 8)`) and the `if`/`select(1)`/`try` wrappers around them, over `path`, `del`, `|=` and `?`. A sibling or an item that can emit nothing *ahead of* the bind (`first(7, B)`, `first(empty, B, 7)`), `limit(2; B, 7)` (which stores `7`) and `nth(1; ..)` keep their refusal. Over a 17,280-row differential grid against `/usr/bin/jq` 1.7.1 (8 leading items x 4 siblings x 10 wrappers x 3 EXTRACTs x 2 sources x 3 contexts x 3 documents): 384 rows that were refused or worded differently now match, none that matched differ, and no row is newly wrongly accepted.
