- **jq: a `reduce`/`foreach`/`until`/`while` that slices its state (`.[1:]`, `.[:-1]`) no longer writes the whole state out as JSON on every step** (#5274). A fold whose UPDATE is a slice with literal bounds took the evaluator's bridge each step, so peeling a 16,000-element array 3,000 times cost 2.4 s. The slice is now a cut of the owned value: an array the step owns outright is cut in place (a `memmove`), a shared one is cut into a new array, and a string is cut by codepoints; `null`, a number or an error stays the evaluator's, in jq mode only. Measured on an Apple M5 Max (release builds, min of 3, ~80 ms process-spawn floor included, output identical to jq 1.7.1): `reduce range(0; 3000) as $i (.nums; .[1:])` 0.41 s → 0.01 s on 4,000 elements and 2.36 s → 0.03 s on 16,000 (jq: 0.005 s); `.[:-1]` 2.40 s → 0.005 s; `until(length < 5000; .[1:])` over 16,000 elements 6.31 s → 0.06 s (jq: 0.008 s). The cut is still O(elements kept) where jq's slice is a view of the same buffer.
