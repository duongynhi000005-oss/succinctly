- **yq: `keys`, `length` and `has` count a mapping's `<<` merge key as the entry it is** (#3556). yq splices a merge for value reads but lists the mapping's own entries in a key list, so with `base: &base {p: 1, q: 2}` and `item: {<<: *base, r: 3}`, `.item | keys` is `["<<","r"]`, `.item | length` is `2`, `.item | has("p")` is `false` and `.item | has("<<")` is `true`; `succinctly yq` answered `["p","q","r"]`, `3`, `true` and `false`. Fixed for one source, a sequence of sources, an own key around the merge key, an inline source and a source that merges another, all captured from yq v4.53.3. `succinctly jq` keeps the merged view. `to_entries`, `pick`, `..` and a mapping a write or `+` already materialized still list the merged members; see `docs/compliance/yq/limitations.md`.
