- **jq: a computed-slice read no longer converts the array per read for `| key`, `| tostring | key`, a document-bound `$a[$i:][0]` or an owned-array `$a | .[$i:][0]`** (#4286). #4251, #4315 and #4321 fused `E[a:b]` followed by `[k]`, `length`, `first` and `last`, but four reads still converted the whole array per read, so a loop over them was quadratic: `.[$i:][0] | key` and `.[$i:][0] | tostring | key` went through the path-context walk, which converted the target array and then the slice; `.xs as $a | $a[$i:][0]` was refused by the fusion's gate (a bound value is a `TrackedVar`, not a plain `Var`); and `$a | .[$i:][0]` over an owned array (a constructed or `map(...)` result) wrote the whole array out and indexed it again. `key` is answered from the slice's range, the bound variable is accepted by the gate, and the owned array is read in place. Measured on a loaded Apple M4 Pro (release builds, interleaved, array of `{"a":{"b":i}}`), see the PR for the growth per doubling. Like the other fused reads, they convert only the element they name (`key` converts none), recorded in `limitations.md`. `key` is fused for jq mode, a non-negative index inside the slice and a read that is the whole pipe; everything else keeps the walk. `path(.[$i:][0])` is #4356.
