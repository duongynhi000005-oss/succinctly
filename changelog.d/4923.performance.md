- **yq: a float in scientific notation, and an ordinary one ending in 3, print without allocating** (#4923). `format_float_yq`'s scientific branch built `{f:e}`, a mantissa `String` for the tie-break correction and the final `mantissa e sign exp` `String`: three to four allocations per number, which #4917 had removed only for ordinary magnitudes. The streaming printer now formats the digits into a stack buffer, asks the tie-break question about them (`shortest_decimal_is_wrong_tie`, the decision `correct_shortest_decimal_tiebreak` already made, split out so it needs no `String`) and writes the `e+NN` spelling piece by piece; an ordinary float whose last digit is `3`, which still built two `String`s for the same question, uses it too. Output is byte-identical (JSON and YAML, 8 MB of mixed numbers) and `format_float_yq` stays the definition the tests compare against, including the exact decimal ties past the threshold. Interleaved A/B, release builds, 15 runs, `yq -p json -o json .` on an Apple M5 Max (instructions retired, median): 2 MB with 20% scientific numbers 0.950 G to 0.886 G (-6.7%), 8 MB 3.699 G to 3.440 G (-7.0%), 8.8 MB all scientific 5.169 G to 3.994 G (-22.7%; wall -17%), and 7.9 MB with none 3.330 G to 3.301 G (-0.8%, the ordinary floats ending in 3). Not measured on x86_64.
