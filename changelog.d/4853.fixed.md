- **jq: `path`/`|=` no longer write the document root when a `//` behind an `if` shares a `foreach` UPDATE pipe with a stage that loses the register (`null` documents)** (#4853, #4843, #4800).
  `null | (. as $x | foreach . as $i (.; ((1 | FE) // 5) | (if . then (1 | FE) // 5 else 4 end); $i)) |= 9` is `{"a":{"a":9}}` in jq and was `9` here, with `path(...)` answering `[]` where jq answers `["a","a"]`; the same for `(.a? // 1) | (if . then (1 | FE) // 5 else 4 end)` and `((1 | FE) // 5) | (if . then 4 else (1 | FE) // 5 end)` (`["a"]`, `{"a":9}`). The branch an `if` runs starts from the register the `if` was entered with, so its outputs state it as a `//` alternate's do: the `//` is now read per output instead of exempting the whole UPDATE from the refusal, and the rows refuse with `Invalid path expression with result null`. The same reading answers the documents where the `if` runs a branch that leaves the register alone (`{"a":1}`, `{"a":null}`, `0` under `if . then 4 else ((1 | FE) // 5) end`), which `main` refused where jq answers.
  Over 115,758 differential rows against `/usr/bin/jq` 1.7.1 (6,431 two-stage UPDATE pipes of `//`, `if` and register-moving stages x `path`/`del`/`|=` x 6 documents), a `main` build as the base: the 5,210 rows that answered where jq answers differently (every one a `null` document) now refuse, none remain, 16,116 rows that differed from jq now match it, and 6,133 rows that matched now refuse (the safe direction): 2,999 are `null`-document `del`s that matched only because deleting the root gave the same `null` as deleting `["a"]`, and the other 3,134 all end in an `if` stage (2,062 with a branch that hands `.` back), which now refuse where `main` answered by exempting the whole UPDATE.
