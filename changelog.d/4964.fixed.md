- **jq: a `?//` chain that destructures an outer `$x` in a `reduce` UPDATE is no longer accepted where jq raises, nor refused where it answers** (#4964, #4953 residual).
  `echo '{"a":1}' | jq -c 'path(. as $x | reduce 1 as $i (0; try ($x as {a:$a} ?// $a | $a)))'` raises `Invalid path expression with result 1`; it answered `[]` here, `del(...)` deleted the document and `(...) |= 9` wrote `9`. A `?//` chain forks the walk, so the register was withheld from the body, alternative one's pattern step on `$x` was refused as exact, the chain retried onto the bare `$a` -- all of `$x`, the register's own node -- and the final emission accepted it. Every alternative starts from the register the chain was entered with (a failed one backtracks), so a chain of plain-variable and literal-key alternatives is read as one path-checked sequence like a single pattern (`foreign_bind_chain_returning_dot`, `update_binds_only_in_tail` and `is_single_output_bind` no longer require one pattern; a computed key still does), and the bare alternative's `.` is left unchecked in a UPDATE whose binds are in tail position. Also answers what was a wrong refusal: `reduce 1 as $i (.; try ($x as {a:$a} ?// $a | .))` on `{"a":1}` is jq's `[]`. Pinned by `tests/jq_cli/i4964.rs`; `scripts/jq-reduce-update-bind-sweep.py` gained `--alt` for `?//` chains (`--alt --sample 3`: 48,384 rows, 2,220 wrong accepts and 456 wrong refusals now match jq, none lost). Still different (recorded in `limitations.md`): a `?//` chain on `.` over a moving source (#4969) and a computed key in an alternative.
