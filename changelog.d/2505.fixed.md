- **yq: an alias mark follows a plain `=` onto a target under a parent the write created, a comma of targets, a negative-index source and a source container that holds an alias** (#2505, #2497 residual).
  `printf 'a: &x 1\nb: *x\n' | yq '.c.d = .b'` printed `c:\n  d: 1` where yq prints `c:\n  d: *x`, and the same for `.c[0] = .b`, `(.c, .d) = .b`, `.c = .b[-1]` over `b: [0, *x]` and `.c = .b` over a block `b:\n  - *x`. The pass that copies the mark read both sides as static paths in the existing tree, so a target the write created had no node to mark, a comma target and a negative index (which needs the array's length) were not paths at all, and a container source was read only for its own mark. The target is now created for the mark, each comma branch is a target, the source is read from the comment tree, and every alias inside a copied container stays one. Values are unchanged (`-o=json` is identical), and an alias still drops when the write destroys its anchor. The other shapes #2505 lists (a constructed or computed right side, `+=`, a copied comment or flow style, the alias group) are unchanged.
