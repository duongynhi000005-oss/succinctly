- **jq: `path`/`|=` no longer write the document root when stages follow a `foreach` whose UPDATE has moved the register (`null` documents)** (#4800, #4797).
  `null | (. as $x | foreach . as $i (.; 1 | foreach ($x as {a:$a} | .) as $y (.; .; .); $i) | .) |= 9` is `{"a":9}` in jq and was `9` here, with `path(...)` answering `[]`; the same behind `| select(true)`, `| first(.)` and `| if true then . else . end`. The refusal the first #4800 entry made for the bare `foreach` did not outlive a stage after it (a lost register state is converted to the frame's loss at each stage, which the terminal never read), so the terminal's `null` carve-out read the last stage's `.` as the root. The frame now keeps that statement (`RegisterLoss::LostOffRoot`) and the pipe's last stage states it again: `path`, `del`, `|=` and `limit`/`?` around them refuse with `Invalid path expression with result null`. A comma beside the `foreach` (`(FE), 7`) and a `//` fallback keep their answers. Over 12,960 differential rows against `/usr/bin/jq` 1.7.1 (2 `foreach` shapes x 9 UPDATE wrappers x 3 sources x 2 EXTRACTs x 5 stage tails x `path`/`del`/`|=` x 8 documents): no row that matched jq changed except the 16 below, no new wrong accept; 32 rows that answered a wrong path now refuse, and 16 rows that matched jq only because `del` of either `null` path is `null` (a `null` document, `del`) now refuse.
