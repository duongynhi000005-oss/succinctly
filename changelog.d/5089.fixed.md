- **yaml: content after a `...` end marker with no `---` is rejected, as yq does** (#5089). `a` / `...` / `b` read as the two documents `"a"` and `"b"`, `a: 1` / `...` / `- b` as `{"a":1}` and `["b"]`; yq prints the first document and stops with `did not find expected <document start>`, and so does `succinctly yq` now (exit 1, with no output: yq has printed the first document before the error, which this does not). A `---` after the `...` still starts the next document. YAML Test Suite `7Z25` (a bare document after `...`, valid YAML 1.2) is now a known failure we take from yq, the same policy as `CFD4`. Not changed: a directive after the marker (`...` / `%YAML 1.2` / `---`) is still accepted, because YAML 1.2 allows it and the spec examples 6.18, 6.21 and 9.6 are written that way. On 60,000 random small documents with document markers: no document with a `---` after the `...` is rejected; about 1,350 are newly rejected that yq rejects too; 8 are rejected that yq accepts by folding the marker into a `--- text` first document (`--- v` / `...` / `b` is `"v... b"` in yq; two documents before) and are recorded in `docs/compliance/yq/limitations.md`; across the 13,498 YAML files on one machine no output changed.
