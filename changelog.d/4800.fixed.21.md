- **jq: a caught foreign-`$x` `foreach` whose pattern lands on an object or an array, in a `foreach` UPDATE over a moving source, raises jq's catchable error for an EXTRACT that navigates the state** (#4800).
  `[path(. as $x | foreach (.a,.) as $i (.; foreach (try ($x as {a:$a} | .)) as $y (.; .; .); .a))?]` on `{"a":{"a":null}}` is `[]` in jq and raised `Invalid path expression near attempt to access element "a" of null` past the `?` (and past a `try`, and a `del(..)?`): the message was jq's, but the resolver had placed the register anywhere in the root, which holds a `null`, so it called the error a guess and made it uncatchable. The pattern's step moves jq's register onto `$x.a`, a container that the `null` or boolean state the `foreach` is handed never is; that landing is now read as the `null`/boolean landing already was, and the pattern's `.` body hands the state on off the register instead of path-checking it, so the next navigation raises jq's own error (`.a`, `(.a)?`, `.[0]`, `$i.a`; bare, behind a `null`/`not` head, a `.` stage, a `label`, `first`, `try` or an emits-nothing comma sibling; `path`, `?`, `try`, `del` and `|=`). Against `/usr/bin/jq` 1.7.1 and `main`, comparing stdout, exit code and the error message, over a 6,000-row grid of the bare shape and 16,287 randomised spellings run on both input routes (38,574 rows): 416 rows move to jq's answer, none move away from it, and no wrong answer is newly accepted. A pattern whose entries land on a container and on an absent key (`{a:$a,b:$b}`) is not read and still raises where jq emits nothing.
