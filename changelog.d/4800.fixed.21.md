- **jq: a caught foreign-`$x` `foreach` whose pattern lands on an object or an array, in a `foreach` UPDATE over a moving source, raises jq's catchable error for an EXTRACT that navigates the state** (#4800).
  `[path(. as $x | foreach (.a,.) as $i (.; foreach (try ($x as {a:$a} | .)) as $y (.; .; .); .a))?]` on `{"a":{"a":null}}` is `[]` in jq and raised `Invalid path expression near attempt to access element "a" of null` past the `?` (and past a `try`, and a `del(..)?`): the message was jq's, but the resolver had placed the register anywhere in the root, which holds a `null`, so it called the error a guess and made it uncatchable. The pattern's step moves jq's register onto `$x.a`, a container that the `null` or boolean state the `foreach` is handed never is; that landing is now read as the `null`/boolean landing already was, and the pattern's `.` body hands the state on off the register instead of path-checking it, so the next navigation raises jq's own error (`.a`, `(.a)?`, `.[0]`, `$i.a`; bare, behind a `null`/`not` head, a `.` stage, a `label`, `first`, `try` or an emits-nothing comma sibling; `path`, `?`, `try`, `del` and `|=`). Against `/usr/bin/jq` 1.7.1 and `main`, comparing stdout, exit code and the error message, over a 6,000-row grid of the bare shape and 16,160 randomised spellings run on both input routes (38,320 rows): 336 rows move to jq's answer, none move away from it, and no wrong answer is newly accepted; one spelling (two `{a:$a,a:$b}` destructures in a comma source behind `not` and a `label`, on both routes) is refused naming a different value, where jq emits nothing. Not read, and unchanged: a pattern whose entries land on a container and on an absent key (`{a:$a,b:$b}`), a source that also destructures a value computed from the marker (`$x.a as {...}`), a container state (`foreach (.,.a)` with INIT `.`), and a `try` around the `foreach` whose handler can emit, whose output jq places at the `try`'s entry (read through it, one such row answered `[]` for jq's `[[]]`; it keeps its refusal).
