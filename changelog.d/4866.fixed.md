- **yq: `kind` reads the node, not a copy of its subtree** (#4866). `kind` converted the whole subtree to JSON before answering, so it cost the size of the node (`[.[] | parent | kind]` over a 4,000-member mapping took 37 s) and an alias read as its target's kind. It now asks the cursor: `alias` for a `*name` reference, as in yq (`b: *x` gave `map`), `seq`/`map` from the type bits without building the node's value, and `scalar` for an explicit `!!null` on a collection. Not part of this change: `..` still descends into a `!!null`-tagged collection where yq does not, and `kind` after `to_entries`, in an assignment's right-hand side and in `--eval-all` still reads an expanded alias, since those routes hold an owned copy.
