- **yq: a bare `sub(re; replacement)` evaluates its replacement once, against the input, and expands it as a Go template** (#4905).
  Real yq evaluates the replacement once against `sub`'s own input (before the input is type-checked or the regex compiled, and whether or not anything matches), takes its first output (an empty stream is `""`; an escape anywhere in it raises), reads no capture object, and runs Go's `ReplaceAllString` with that text as the template (`$1`, `${name}`, `$$` expand). `succinctly yq` evaluated the replacement per match against the capture object, as jq does, so the two agreed only for a literal: `"a1b" | sub("a"; .)` printed `"{}1b"` where yq prints `"a1b1b"`, `sub("(?<x>a)"; .x)` printed `"a1b"` (yq `"1b"`: `.x` is absent on a string), `sub("a"; length)` read the capture object's length, `sub("a"; ("X","Y"))` printed two strings (yq the first), `sub("z"; error("boom"))` never ran its replacement (yq raises), and `sub("(b)"; "$1")` kept the `$1` as text. 83 rows captured from yq v4.53.3 now match, in `tests/yq_cli/i4905.rs`. jq mode and the 3-argument form are unchanged; yq's `gsub` extension keeps the per-match model. Not changed here (recorded in `limitations.md`): yq keeps an unknown escape in a string literal (`"<\\1>"`), which this parser rejects.
