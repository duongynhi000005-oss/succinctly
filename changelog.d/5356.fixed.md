- **yq: a UTF-8 byte-order mark at the front of a YAML file is skipped** (#5356). It stayed in the document: it became part of the first key (`.a` was `null` where yq gives `1`, `keys` listed `"﻿a"`), a mark before `---` or a leading comment was a YAML parse error, a file that was only the mark read as the string `"﻿"`, and `-i` wrote the key back quoted. Every input route now drops it, from each file separately as yq does (stdin, the default route, `--eval-all`, `--slurp`, `-i`), and `yq-locate` skips it too, so its offsets and columns and `at_offset`/`at_position` count from the first byte after it, as `jq-locate`'s do (#5313); the `json` format adds `"bom_length": 3` for such a file. A mark in the middle of a file stays data, and a JSON document with one is still refused, as in yq. One residual: yq prints no leading `---` for a BOM-prefixed file that starts with one, and this prints it (#5357).
