- **jq: `reduce .[] as $x ({}; .[$x.name] |= (. // []) + [$x.id])`, `reduce .[] as $x ({}; setpath([$x.id | tostring]; 1))` and `reduce .[] as $x ([]; . += [$x])` are linear** (#5271). Each declined the in-place write of a fold step and copied the accumulator on every step, quadratic in the number of steps (jq: linear, or quadratic only for `. += [$x]`). An array literal in a state-reading operand (`[]`, `[$x.id, $x]`) is now one value like the rest, `setpath(P; V)` takes the in-place step with `P` and `V` evaluated before the write, and `. += X` (and `. |= . + X`) combines the moved state when both sides are arrays, objects or strings; any other pairing, and a `setpath` or operand that raises, still takes the evaluator's route and text. Measured on an Apple M5 Max (release builds, interleaved, min of 3, ~80 ms process-spawn floor included, output identical to jq 1.7.1): the grouping idiom 0.96 s → 0.08 s at 5,000 records, 3.69 s → 0.08 s at 10,000, 15.2 s → 0.08 s at 20,000 (jq: 0.09 s); `setpath([$r.name]; $r.score)` 0.73 s → 0.09 s, 2.73 s → 0.09 s, 10.9 s → 0.08 s (jq: 0.09 s); `. += [$r.score]` 0.42 s → 0.08 s, 1.43 s → 0.09 s, 5.56 s → 0.08 s (jq: 0.48 s at 20,000); `. += {($r.name): $r.score}` 0.76 s → 0.09 s, 2.75 s → 0.08 s, 11.0 s → 0.09 s (jq: 1.46 s).
