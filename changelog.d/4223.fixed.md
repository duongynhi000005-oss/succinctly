- **yq: a write through `..` reaches an anchored node once** (#4223).
  `printf 'anchors:\n  base: &b {p: 1, q: 2}\n  copy: *b\n' | yq '(.. | select(tag == "!!int")) |= . + 1'` is `p: 2, q: 3` in both mappings; `succinctly yq` gave `p: 3, q: 4`, because `..` resolved the expanded copy's children as targets as well and the alias redirect then sent each onto the anchor's node, which was incremented twice (`+= 1`, `-= 1`, `*= 2` and `|= (. + 1)` the same; `= 9` and `del()` landed on the same value either way). The paths a `..` resolves below an alias position that is still its anchor's copy are now dropped from the targets, as yq's descent stops at the alias node; explicit paths through an alias (`.copy.p`, `.[] .p`) accumulate as before. Documents without aliases, and `jq` mode, are unchanged. The merge-key case of #4223 (`<<: *b` listed and written through) is still open.
