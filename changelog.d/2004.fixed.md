- **yq: `--colors -0` writes the clean results before a NUL-bearing one, as yq does** (#2004). `succinctly yq --colors -0 '.[]'` over `["hello", "wor\0ld", "x"]` printed nothing and failed on the NUL, where yq prints `hello\0` and then fails (exit 1, same message); the colored render was scanned whole before anything was written, so one NUL discarded every earlier result. The results that end before the first NUL are now colorized and written, then the run stops with the same error. Output without a NUL, and the memory cost of coloring, are unchanged.
