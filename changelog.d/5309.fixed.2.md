- **jq: `fromjson` and `tonumber` name the fault jq's JSON parser names** (#5309). A refused text used to read `Invalid numeric literal at EOF at line 1, column N` whatever was wrong with it; jq reports the first fault its push parser meets, where it met it: `a,b` stops at the comma (`Invalid numeric literal at line 1, column 2`), `[1,` is `Unfinished JSON term at EOF`, `1 2` is `Unexpected extra JSON values`, and so on for unmatched or mismatched closers, a missing separator, a trailing comma, a bad escape or surrogate, an unfinished string and an over-deep document. The new `src/jq/parse_message.rs` ports the error behaviour of jq 1.7.1's `jv_parse.c` and runs on the refusal path; it matches jq on about 430,000 strings (every one of up to six characters over a structural alphabet, and random ones from a pool of numbers, literals, escapes, newlines, BOMs and NULs). 31 probes added to the error-message corpus; `docs/compliance/jq/limitations.md` no longer lists these as an approximation.
