- **jq: input that starts with a UTF-8 byte-order mark is parsed, as jq does** (#5291). `printf '\xef\xbb\xbf{"a":1}' | succinctly jq -c .` failed with `Invalid JSON text` (`--validate` with `expected JSON value, found '\u{feff}'`), which is how PowerShell's `Out-File`, Notepad and .NET serializers write JSON. The BOM is skipped on the default, `--slurp`, `--stream`, `input`/`inputs` and `--validate` routes, from stdin and from files, and in `--slurpfile`, `--argjson`, `--jsonargs` and an `import ... as $d` data file. Like jq's one parser over every input file, only the front of the whole stream is skipped (the first file with any bytes): a BOM at the front of a later file is still a byte inside the stream and is refused. `-R` still reads it as an ordinary character, and `--seq` keeps its own BOM accounting.
