- **jq: a `foreach` UPDATE that ends on a bind of a `$x` marker's body `.` is no longer refused when its EXTRACT is judged** (#5111). `path(. as $x | foreach . as $i (.; 1 | ($x as {a:$q} | .); $i))` on `null` is `["a"]` in jq: UPDATE's output is stored as the next state without a path check, so the `1` the bind's body hands on goes unchecked and EXTRACT's `$i` is judged at the register the bind moved to. It raised `Invalid path expression with result 1`, so `del(..)` (`null`) and `|= 9` (`{"a":9}`) failed too, and `[path(..)?]` was `[]` for `[["a"]]`. `resolve_reduce` has had this reading for a `reduce` UPDATE since #4901; a `foreach` with an EXTRACT now gets it (a two-argument `foreach` emits UPDATE's output, which is checked, and keeps the refusal). Over 22,000 grid rows (document x bind site x head stage x bind x source x INIT x EXTRACT x context) against `/usr/bin/jq` 1.7.1 and a `main` build: about 740 rows that were refused or answered wrongly now match, none that matched differ, and four seeds of random fold programs moved no matching row.
