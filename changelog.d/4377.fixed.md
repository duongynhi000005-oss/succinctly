- **yq: `-P` moves a flow collection's trailing comment to the next line, as yq does** (#4377). `printf 'a: [1, 2] # ec\nb: 1\n' | yq -P '.'` prints `b: 1 # ec`; `succinctly yq` printed `# ec` on a line of its own under `- 2`, and a navigated flow collection (`.a`) printed it after its last element where yq drops it. yq's encoder has no line for the comment once the brackets are gone, holds it, and writes it at the end of the next line that has no comment of its own (the next key's line for a collection, its value line otherwise), losing it when nothing follows; a commented scalar keeps its line and the comment waits, a comment on a collection's key overwrites it, an alias is skipped, and an empty `[]`/`{}` stays flow with its comment. Writes (`.z = 1`) and multi-document input follow the same rule. Not part of this change: a comment written *inside* a flow collection (`[1, # note`), which the parser does not keep, and the `{}`/`[]` value that yq writes on the line after its key.
