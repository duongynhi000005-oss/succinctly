- **yaml: an own-line plain scalar continued by a `key: value` line is rejected, as yq does** (#5083). `k:` / `  a` / `  z: 1` read as `{"k":"a z"}`, `k:` / `  a` / `  k: z` as `{"k":"a k"}` and `k:` / `  a` / ` - k: z` as `{"k":"a - k"}`, the `: 1` silently gone; yq stops at the `:` with `mapping values are not allowed in this context`, and so does `succinctly yq` now (#5064 did the same for a value on the key's line). The value on the line below its key was scanned by a separate path that never ran the content check. A `:` with no space after it (`z:b`, `http://x`) is still text. Not changed, still accepted where yq rejects (filed): the same shape as a sequence item's value (`-` / `  a` / `  z: 1` is `["a"]`), a quoted own-line value (`k:` / `  "a"` / `  z: 1`), a compact mapping's own-line value (`- k:` / `    x` / `    y: 1`) and a sequence item between two open blocks (`- k: a` / ` - z`). Checked against 12,671 YAML files on disk and a randomized sweep of 3,000 own-line-value documents against yq v4.53.3: 325 more documents rejected that yq rejects, none newly rejected that yq accepts.
