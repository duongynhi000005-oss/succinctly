- **yq: an array read by a string key reads the index the key spells** (#4274). yq parses the key with `parseInt64`, so `[10,20,30] | .["1"]` is `20`, `.["-1"]` is `30`, `.["01"]`, `.["+1"]`, `.["0x1"]` and `.["0o1"]` are `20`, and `.["1_0"]` and `.["5"]` are `null`; `" 1"`, `"x"`, `"1.0"` and a value past `i64` stay errors. `succinctly yq` raised `Cannot index array with string` for every one of them, whether the key was a literal, `.[$k]`, `.[("1")]`, a computed array or the slice of one. `succinctly jq` still raises, as jq does. Only reads: `.["1"] = 9` and `del(.["1"])` still raise, `.[1.5]` still truncates where yq raises, and the refusal keeps its own wording (recorded in `docs/compliance/yq/limitations.md`).
