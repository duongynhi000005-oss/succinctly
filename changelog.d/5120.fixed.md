- **jq: a `foreach` UPDATE or EXTRACT that destructures the register `$x` beside a computed `INIT` is no longer read as raising** (#5120). `(. as $x | foreach 1 as $i ({}; try ($x as {a:$q} | .); .)) |= 9` on `{"a":0,"b":false}` is jq's `Invalid path expression with result {}` (exit 5) since the fold's source does not move the register, `$x` is bound at it, the pattern's step passes and UPDATE emits its computed state. It left the document alone and exited 0, `[path(..)]` printed `[]` and `path(..)` nothing, the same for `INIT 0`, `null`, `[]` and `"s"` and for `($x as P | .)?`; the uncaught `$x as P | .` now fails with jq's `with result` message. The register is handed to a `foreach` body that is a chain of single-output binds, as #4901 did for a `reduce` UPDATE. On a 2,700-row grid (bind site x INIT x source x UPDATE x EXTRACT x context) against `/usr/bin/jq` 1.7.1 and a `main` build, 450 rows that were wrong now match and none that matched differ. Of 24,000 random fold programs 37 more match; 4 that matched `main` only because it answered with an empty path (`del`, which jq no-ops) now refuse loudly, as do the rows of #5121 that were a silent no-op (a `null` or boolean emission after the bind passed, which jq accepts at the register the bind moved to, so `= 9` writes where this refuses).
