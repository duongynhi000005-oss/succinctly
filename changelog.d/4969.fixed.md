- **jq: a `?//` chain that destructures `.` in a `reduce` UPDATE over a source whose first element is the accumulator itself is no longer accepted where jq raises** (#4969, #4964 residual).
  `echo '{"a":1}' | jq -c 'path(reduce .. as $i (.; try (. as {a:$a} ?// $a | $a)))'` raises `Invalid path expression with result 1`; it answered `[]` here, `del(...)` deleted the document and `(...) |= 9` wrote through it (`{"a":{"b":1}}` and `(.,.a?)`, `first(..)` sources likewise). `..` yields `.` first, so at step 1 the accumulator (INIT `.`) is jq's register and the first alternative's pattern step passes; the binary marked the step as one whose source moved the register off the accumulator (true for `.[]?`, whose elements are children), refused alternative one as exact and retried onto the bare `$a`, all of `.`, keeping the root through every later step. The move marks are now skipped for the step where the element is the register's own node and the accumulator is already at it. Pinned by `tests/jq_cli/i4969.rs`. Still different (recorded in `limitations.md`): some `?//` chains ending in `.` over such a source are refused where jq answers, and the wording of the error names the accumulator rather than jq's `null`.
