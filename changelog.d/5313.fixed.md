- **jq-locate: offsets count from after a leading UTF-8 byte-order mark** (#5313). `succinctly jq` has dropped the mark before indexing since #5291, so `at_offset(n)` and `at_position` counted from the first byte after it while `jq-locate --offset n` counted from the first byte of the file, and the two named different nodes (3 bytes apart) on the same BOM-prefixed file. `jq-locate` now skips the mark too, so `--offset`, `--line`/`--column` and the `json` format's byte range agree with `at_offset`/`at_position` (and with an editor, which does not show the mark); offsets 0-2 used to be inside the mark and found nothing. This is a coordinate-system choice with no jq oracle (jq has neither tool); it matches `yq`'s front-matter handling, which counts from the stripped text.
