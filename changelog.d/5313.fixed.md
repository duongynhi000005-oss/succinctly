- **jq-locate: offsets count from after a leading UTF-8 byte-order mark** (#5313). `succinctly jq` has dropped the mark before indexing since #5291, so `at_offset(n)` and `at_position` counted from the first byte after it while `jq-locate --offset n` counted from the first byte of the file, and the two named different nodes (3 bytes apart) on the same BOM-prefixed file. `jq-locate` now skips the mark too, so `--offset`, `--line`/`--column` and the `json` format's byte range agree with `at_offset`/`at_position` (and with an editor, which does not show the mark); offsets 0-2 used to be inside the mark and found nothing. The `json` format adds `"bom_length": 3` for a file that has a mark, so a script slicing the file with `byte_range` can add it back. This is a coordinate-system choice with no jq oracle (jq has neither tool); `yq-locate` and `yq`'s `at_offset` still count the mark as part of the document (#5356).
