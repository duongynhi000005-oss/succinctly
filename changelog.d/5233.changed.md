- **jq: a program whose path target is more than navigation runs on the path-mode interpreter or is refused; the shipped resolver no longer answers it** (#5233). Since #5223 such a program (`path(f)`, `del(f)`, `pick(f)` or `f |= g` for an `f` that binds, folds, branches or calls a function) ran on the path-mode interpreter unless it also used a builtin the interpreter declines, or its document could not be decoded whole; both fell back to the shipped resolver, whose answers differ from jq's (#5239). Now a program that also uses `key`, `file_index`, bare `path`, `parent` or a cursor-metadata builtin (`line`, `column`, `document_index`, `anchor`, `style`, the comment builtins, `at_offset`, `at_position`) is refused with an error naming the builtin: each is a succinctly extension jq 1.7.1 rejects at compile time (`key/0 is not defined`). The same builtins beside only navigation targets answer as before. A document with a lone surrogate or nesting past 256 levels raises the decode error for such a program, as jq rejects the document when it parses it. The first ~800 lines of the resolver's jq-mode-only code are removed.
