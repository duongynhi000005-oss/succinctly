- **jq: a dynamic path program that also uses a succinctly extension builtin is refused** (#5233). Since
  #5223 a jq program whose `path`/`del`/`pick` or assignment target binds, folds, branches or calls a
  function runs on the path-mode interpreter, except one that also used `key`, `file_index`, `parent`,
  bare `path` or a cursor-metadata builtin (`line`, `column`, `at_offset`, ...), which fell back to the
  old path resolver. That fallback is gone: such a program is now rejected before any input is read,
  with `key is not supported in a program whose path expression does more than navigate` and jq's
  compile-error status (exit 3), wherever the extension sits in it.
  jq 1.7.1 rejects every one of these programs at compile time (`key/0 is not defined`); the same
  extensions beside navigation-only targets (`(.a[] | select(. > 1)) |= (parent | length)`) still
  answer. A dynamic path program over a document with a lone surrogate or nesting past 256 levels now
  raises the decode error instead of answering from the parts it read; jq rejects such a document when
  it parses it, with its own wording. yq mode is unchanged.
