- **jq: an object key may be an interpolated string or a format applied to one** (#5298). `{"a","b","a$\(1+1)"}` was a compile error (`invalid escape sequence '\('`); it is `{"a":1,"b":2,"a$2":4}` on `{"a":1,"b":2,"a$2":4}`, as in jq, and so are `{"a\(.k)": 1}` (a key with a value, which failed the same way), `{"\(.k)"}`, `{@base64 "x\(.k)"}` and a multi-output key with a value (`{"a\(1,2)": 3}`). A shorthand whose string is not surely one value (`{"a\(1,2)"}`, `{"a\(.xs[])"}`) is refused at compile time rather than pairing every key with every value, as jq's one-read-per-key shorthand does not. Differential against jq 1.7.1 over 840 generated objects on five inputs: no difference but that refusal.
