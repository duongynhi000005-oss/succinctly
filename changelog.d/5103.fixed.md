- **jq: a slice that spans the whole of a non-empty array is read as the array it slices in path expressions** (#5103). jq's array slice shares the array's buffer, so `.a[0:]` of a non-empty array is `.a` itself (`jv_identical`), while the slice of an empty array is a fresh `[]`. A `$x` bound at one spelling and used at the other was refused: `path(.a as $x | .a[0:] | $x)` on `{"a":[{"b":1},{"b":1}]}` is `["a",{"start":0,"end":null}]` in jq and raised `Invalid path expression with result [...]` here, `del(.a as $x | .a[0:] | $x)` now deletes the slice (`{"a":[]}`) as jq does, and `try path(.a as $x | .a[0:] | foreach ($x as [$q] | .) as $y (.; .a?; 1)) catch "c"` is jq's `"c"` where it escaped the `try`. A `$x` bound at an equal-valued sibling, or at the empty array whose slice is fresh, is now known to be another node, so its refusal is the catchable one jq raises. jq copies a slice whose offset reaches 65,536 instead of viewing the array, so each evaluation of `.a[65536:]` is a new array: `path(.a[65536:] as $x | .a[65536:] | $x)` now refuses as jq does, where it answered (and `del` deleted through it), while the same slice bound once as `. as $x` still answers. A copied slice spelled alike on both sides (`.a[70000:] as $x | .a[70000:] | $x as [$q] | .`) now refuses loudly where `main` matched jq's catchable error by coincidence: positions cannot tell one evaluation of it from two. Over 29,702 rows of a slice differential grid against `/usr/bin/jq` 1.7.1 and a `main` build, 670 rows that were refused or answered differently now match, 641 more give jq's error message, and no row that matched differs; over 1,440 rows on a 70,003-element array, 76 rows now match and those 12 refuse.
