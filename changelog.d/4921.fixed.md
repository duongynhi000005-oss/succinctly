- **yq: an overflowed integer spelled with a `+`, a leading zero or an explicit `!!float` tag keeps its digits through `tostring`, interpolation and `join`** (#4921, #1129 residual).
  `a: +99999999999999999999 | .a | tostring` answered the rounded double `100000000000000000000.0` (and so did `"\(.a)"`, `join`, `sort`, `unique`, `|= tostring`); yq answers the text as written, `+99999999999999999999`, and the same for `0099999999999999999999`, `-0099999999999999999999` and `a: !!float 99999999999999999999`. #1129 kept the digits only for a plain `[-]digits` spelling because the reindex bridge reads a literal's text as JSON: a leading zero is read there as it reads `007`, and the bridge now also keeps a `+` on this one shape in yq mode, so a value that crosses it (`--eval-all`, `.b = .a`, `[.a] | join(",")`) still prints the `+`. `-o=json`, `@json` and `-r -o=json` are unchanged (the double, or the text under `-r`). 100 rows captured from yq v4.53.3 and matching now, in `tests/yq_cli/i4921.rs`. Still different (recorded in `limitations.md`): a `!!float` tag is not printed on a nested value (`[.a]` is `- 99999999999999999999` where yq prints `- !!float 99999999999999999999`), as for every tagged float that keeps a literal (`!!float 5.0`).
