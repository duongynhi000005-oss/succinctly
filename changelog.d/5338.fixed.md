- **jq: an `import`/`include`'s `search` metadata is honoured, as jq does** (#5338). `import "m" as m {search:"./L1"}; m::a` looked `m` up on the default list (the current directory, then `-L`) and answered the current directory's `m.jq`; jq looks only in the directories `search` names. A string is a list of one, an array contributes its string entries, and a value of any other kind is an empty list, so `{search:"./nonexist"}` is `module not found: m` even where the current directory holds `m.jq`. An entry is `~/...` under `$HOME`, `$ORIGIN/...` under jq's own directory, an absolute path as it stands, exactly `.` the working directory, and anything else relative to the directory of the file that holds the directive: a module's own directory, the `-f` file's directory under `-f`, or the working directory. `include` and a data import take `search` too, and a `module {search: ...};` header is not read.
