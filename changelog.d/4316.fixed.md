- **jq: a value spanning two input files is on the line of the file it completes in** (#4316). `input_line_number` and the `(at <file>:<line>)` marker counted the newlines of the part that moved onto the later file (#4305): `[1,\n` then `2]\n` was line 2 where jq 1.7.1 says 1, and `{"a":\n` then `1}\n` likewise. The value before a spanning one lost the newline its read takes from the part that moved on (`1\t[2,\n3,` then `4]\n`: the `1` is on line 1 in jq, 0 here), and `<unknown>` at the end of input was decided on the stitched last file, so a 4094-byte file with a `1` moved onto it read as a full 4095-byte read. Each file's lines, reads and end-of-input tail are now counted as jq counts them, over the file as it was on disk. A differential against jq 1.7.1 over 1,250 random two- and three-file splits (values with newlines, 4090-4100 bytes of padding), each run under six programs, had 562 differing runs before this and none after.
