- **jq: a nested `foreach` that destructures a navigation of the root-bound `$x` in a `foreach` UPDATE answers where jq answers instead of refusing** (#4827, #4800).
  With `P = null | foreach (($x.a) as {a:$a} | .) as $y (.; .; .)`, `path(. as $x | foreach .a as $i (.; P; .))` on `{"a":{"a":null}}` answers `["a","a"]` in jq and raised `Invalid path expression near attempt to access element "a"` here, as did `del(...)` and `(...) |= 9` (likewise `($x|.a)` and `$x | .a` as the destructured source): the outer source steps the register onto `.a`, and the node `$x.a` hands on is that very `jv`, so jq's `path_intact` passes the pattern's step. The resolver could place a bare `$x` against the register but not a navigation of it, and took the step for a copy's. It now compares the storage the navigation yields with the register's, jq's pointer rule, so a `$x.c` that merely equals the register in value, and the root `$x` itself, still refuse. A `1` value head in the same position now raises jq's `with result` message where it said `near attempt to access element`.
