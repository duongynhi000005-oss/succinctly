- **yq: `tostring` of an array or object is its YAML, not JSON** (#1130). `[1, 2] | tostring` was `"[1,2]"`, jq's text; yq answers the YAML it would print, `"- 1\n- 2"`, with the trailing line break chomped (`{"a": [1]}` is `"a:\n  - 1"`, `[1.0 * 3]` is `"- !!float 3"`, `[]` is `"[]"`). A container the source wrote in flow style stays flow (`b: [1, 2]` gives `"[1, 2]"`). The text comes from the CLI's own YAML writer, and the owned fast paths (`select(tostring | ...)`, a `reduce` body) share one definition with the main route. jq mode still JSON-encodes. Not part of this change: a flow container nested in a block one, or rebuilt by `with_entries`, prints block; `-I` is ignored; and string interpolation of a container still JSON-encodes.
