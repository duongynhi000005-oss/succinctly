- **jq: a `reduce` whose source moves the register no longer accepts an UPDATE that destructures `.` in an output it then discards** (#5141). `(reduce .a as $i (.; (. as {b:$q} | $q), .)) |= 9` on `{"a":{"b":1},"b":2}` raises `Invalid path expression near attempt to access element "b" of {"a":{"b":1},"b":2}` in jq, and wrote `9` (`path(..)` answered `[]`, `del(..)` answered `null`): the source leaves jq's register on `.a` for the whole step, so the UPDATE's `. as {b:$q}` indexes the accumulator, which is not the register, and raises. A `reduce` keeps only the last output of UPDATE, and the final `.` passes its check, so the raise of the discarded item was never modelled. A destructuring bind of `.` on a path that always runs (a comma's items, a pipe's head, `first`/`limit`/`nth(0)`, a `label`, a `try`, an `if` whose branches both do, a `//`'s left operand) now counts as navigating the accumulator, and so do the builtins jq defines with `.[..]`/`.[]` on their input and no condition on its contents (`map`, `add`, `first`, `last`, `nth`, `flatten`, `join`: `(reduce .a as $i (.; (map(.)), .)) |= 9` raised in jq and wrote `9`), so the step is resolved against the register the source left. A source that moves nothing (`(1,2)`), a `?//` chain (it retries on the raise) and a `foreach` UPDATE are unchanged. Over 24,000 grid rows (document x bind x wrapper x fold kind x moving source x INIT x context) against `/usr/bin/jq` 1.7.1 and a `main` build: 230 rows that were refused or answered wrongly now match, none that matched differ.
